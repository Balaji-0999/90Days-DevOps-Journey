# Docker Interview & Revision Questions — Answers

## 1. What is a Docker image?

A **Docker image** is a read-only package that contains everything needed to run an application, such as:

* Application code
* Dependencies
* Libraries
* Configuration
* Runtime
* Required filesystem files

An image is used as the **blueprint/template for creating containers**.

Example:

```bash
docker pull nginx
```

This downloads the Nginx Docker image.

---

## 2. What is a container?

A **container** is a running or stopped instance created from a Docker image.

It provides an isolated environment where an application can run.

Example:

```bash
docker run -d --name my-nginx nginx
```

Here:

* `nginx` → Docker image
* `my-nginx` → container name
* The container is created from the Nginx image.

---

## 3. What is the relationship between an image and a container?

Think of it like this:

```text
Docker Image
     ↓
   docker run
     ↓
  Container
```

An **image is the blueprint**, while a **container is the actual instance created from that blueprint**.

One image can be used to create multiple containers:

```text
             nginx image
           /      |      \
          ↓       ↓       ↓
      nginx-1  nginx-2  nginx-3
```

---

## 4. Why are Docker images made of layers?

Docker images are divided into **layers** so Docker can reuse unchanged parts of an image.

For example:

```text
Application Layer
        ↓
Dependencies Layer
        ↓
Python Layer
        ↓
Ubuntu Base Layer
```

Each Dockerfile instruction can create a new layer.

Benefits:

* Saves storage space
* Makes image builds faster
* Allows Docker to reuse existing layers
* Makes image sharing more efficient

---

## 5. Why is image caching useful?

Docker **caches image layers** that have already been built or downloaded.

For example, if Docker already has the Ubuntu base layer, it doesn't need to download/build it again.

This makes:

```bash
docker build .
```

much faster when most of the Dockerfile hasn't changed.

**Main benefit:** less time and less network usage.

---

## 6. Why is Alpine smaller than Ubuntu?

Alpine Linux is designed to be **minimal** and contains fewer packages and utilities by default.

Ubuntu is a more feature-rich general-purpose Linux distribution and includes many more packages.

Therefore:

```text
Alpine → Minimal → Smaller image
Ubuntu → More packages → Larger image
```

A smaller image can mean:

* Faster downloads
* Faster container startup
* Less disk usage

However, **smaller doesn't automatically mean better**. You should choose the base image according to your application's requirements.

## 7. What's the difference between `docker create` and `docker run`?

### `docker create`

Creates a container but **does not start it**.

```bash
docker create --name my-nginx nginx
```

Container state:

```text
Created → Not Running
```

### `docker run`

Creates **and starts** a container.

```bash
docker run -d --name my-nginx nginx
```

Container state:

```text
Created → Started → Running
```

Easy way to remember:

> `create` = create only
> `run` = create + start

---

## 8. What's the difference between `docker stop` and `docker kill`?

### `docker stop`

Gracefully stops a running container.

```bash
docker stop my-nginx
```

Docker first gives the application time to shut down properly.

### `docker kill`

Immediately sends a kill signal to the container's main process.

```bash
docker kill my-nginx
```

Easy way to remember:

```text
docker stop → Graceful shutdown
docker kill → Immediate termination
```

Use `stop` when possible because applications get an opportunity to clean up properly.

---

## 9. What's the difference between `docker stop` and `docker rm`?

### `docker stop`

Stops the container but **does not remove it**.

```bash
docker stop my-nginx
```

The container still exists and can be started again:

```bash
docker start my-nginx
```

### `docker rm`

Removes the container.

```bash
docker rm my-nginx
```

After removal, that container no longer exists.

Typical workflow:

```text
Running
   ↓
docker stop
   ↓
Stopped
   ↓
docker rm
   ↓
Removed
```

---

## 10. What does `docker logs -f` do?

`docker logs` displays logs generated by a container.

```bash
docker logs my-nginx
```

The `-f` means **follow**.

```bash
docker logs -f my-nginx
```

It continuously displays new log entries as they are generated.

It is similar to:

```bash
tail -f
```

Useful for watching an application's logs in real time.

---

## 11. What's the difference between `docker exec` and `docker run`?

### `docker run`

Creates and starts a **new container** from an image.

```bash
docker run -it ubuntu bash
```

### `docker exec`

Runs a command **inside an already running container**.

```bash
docker exec -it my-nginx bash
```

Relationship:

```text
docker run
    ↓
Creates new container

docker exec
    ↓
Enters/executes command inside existing container
```

---

## 12. Why would you use `docker inspect`?

`docker inspect` provides detailed low-level information about Docker objects such as containers, images, networks, and volumes.

Example:

```bash
docker inspect my-nginx
```

It can show information such as:

* Container ID
* IP address
* Network configuration
* Port bindings
* Mounts
* Environment variables
* Container state
* Image information

It is especially useful for **troubleshooting and debugging**.

---

## 13. How do you find container IP information?

You can use:

```bash
docker inspect my-nginx
```

Or extract the IP directly:

```bash
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-nginx
```

You can also inspect the container's network:

```bash
docker network inspect bridge
```

These commands help when troubleshooting container-to-container communication.

---

## 14. How do you see Docker disk usage?

Use:

```bash
docker system df
```

It shows disk usage by Docker resources such as:

* Images
* Containers
* Local volumes
* Build cache

For more detailed information:

```bash
docker system df -v
```

This is useful for finding what is consuming Docker's disk space.

---

## 15. Why should `docker system prune` be used carefully?

`docker system prune` removes **unused Docker resources**.

Example:

```bash
docker system prune
```

It can remove unused:

* Containers
* Networks
* Images
* Build cache

Because it deletes resources, you should understand what will be removed before running it, especially on a **production server**.

You can preview Docker disk usage first:

```bash
docker system df
```

Then decide whether cleanup is necessary.

### Important

Avoid blindly using aggressive cleanup commands such as:

```bash
docker system prune -a
```

because `-a` allows Docker to remove unused images that are not currently associated with containers.

**Simple rule:**

```text
docker system df
        ↓
Check what is using space
        ↓
Decide what is safe to remove
        ↓
docker system prune
```
